2026-09-24：继承已确认的入驻 V2 视觉，推广到所有导航页。交易与服务的园区运营、客户端、支付平台及财务回调由验收工具模拟；未提供真实 API 的内容只做前端演示。附加能力选择延续既有约定，不重复询问。

## 经批注确认的设计判断（2026-09-24）

- 先按用户的决策顺序组织页面：对象名称和当前状态优先，分类、时间及补充描述降为次级；主操作靠近页面标题或当前对象，不悬在无关联的位置。
- 简洁是信息取舍与稳定对齐，不是把字段平铺。首屏先看任务和状态，编辑表单按真实工作步骤分组，列表保持可扫描的密度，并为数量增长准备明确的分页或筛选方式。
- 一级、二级页面不展示不可交互的面包屑；确需三级导航时，补可点击的返回路径。页面标题图标与侧栏的同一业务图标一致；区块标题图标传达各自语义，子字段不用重复图标。
- 图片上传入口与预览区域优先合一，保存前后均可辨认结果；图片支持查看大图。操作图标与文字留约 4px 间距，状态图标与文字垂直居中。
- 反馈消息和二次确认属于全站共享组件：标题显著、图文对齐、长文案可读、操作结果明确。按钮与标签延续入驻 V2 的圆角矩形，颜色只强调当前状态和主要动作。
- 我的园区的“查看园区客户端”在 PRD 中规定同号 SSO 跳转；是否当前页打开还是新页打开尚未定。当前演示沿用站内跳转，待园区客户端接入方案确定后决定打开方式与返回路径。
- 钱包内部由支付平台提供，供应商端只设计承载、开户状态和未接入状态，不用本地订单估算资产、明细或提现规则。

## 本轮强化的判断规则（2026-09-24）

- 用亲近关系组织信息：标题、说明、字段或状态在同一组内收紧；不同任务组之间拉开并使用边界。视觉焦点先落在对象与当前任务，避免整页等权的空旷平铺。
- 字段宽度匹配输入内容和阅读成本。金额、单位、天数紧凑排列，长描述占宽；校验信息出现在具体字段旁，并把首个错误带入视野。
- 服务状态使用全站一致的语义色与可读文字；弱操作始终有可识别的点击形态。空列表与验收模拟空态都显示缺省图标。
- 发布表单的未保存返回提供暂存、放弃、继续三种路径；验收工具能填入示例、直达指定步骤并切换有数据、加载、空态、异常。示例数据应覆盖多个目录和关键状态，补齐动作保留当前主体已有记录。

## 桌面密度与订单阅读（2026-09-25）

- 管理页共用 `--biz-content-width: 1440px`；入驻向导、服务编辑器等长表单保留适合阅读的内部字段宽度。桌面断点为 1200px；达到该宽度后网格按可用空间重排。更窄窗口保持桌面内容宽度，根页面不横向滚动，只有主内容区滚动。主滚动区保留滚动条槽位，空/长列表切换不改变水平位置。
- 服务园区只显示一行：前两项允许名称省略，状态始终完整，剩余园区在弹层查看；不可折行。右侧销量和操作右对齐，操作左至右为上架、下架、编辑、删除（按资格显示），详情由封面和服务名称进入。
- 图片上传使用统一的 160×112 图片框，空态图标与文字居中；已有图片整框预览，悬停显示替换入口。应用于服务封面、媒体入口、案例封面及店铺图片。证件上传保持原业务组件。
- 订单列表优先回答“哪笔订单、提供什么、如何履约、多少钱、当前什么状态、现在做什么”。主订单状态与退款状态同时展示；列表金额使用订单总额、剩余实付、待付与已退，明细下沉到详情。
- 详情以阶段收付款表、可展开的交付阶段、退款记录表组织内容。当前待办集中在顶部，右栏固定订单概要；去掉并列大数字卡片和重复区块标题，保持固定五页签顺序。
- PRD 正文 §6.5.5 描述本期单期交易，用户明确追加多期演示验证。多期能力属于前端演示扩展，正式阶段计划与回调字段待接口确认。

## 2026-09-27 · 本轮补充约束

- 已加入园区始终在可申请园区之前。已加入卡片随桌面宽度两列/三列；申请卡片较小；统计图标紧邻指标名称。
- 工作台以真实待办推动操作：退款优先，随后签约、交付；经营概览为当前主体累计数据，不造趋势或增长率。
- 消息确认框的风险图标紧邻说明并与首行对齐；标题 18px / 700。普通弹窗固定头尾，正文独立滚动；文字按钮两侧留白 10px。
- 服务媒体网格按可用宽度增加列数；区域/案例标签按文字测量和容器宽度计算展示数量。FAQ 单项展开，列表底部可继续添加。
- 商户变更直接复用入驻 StepView 与 OnboardingShell。四类档案只读，变更审核通过才覆盖生效数据；证件原文件保存在本地 IndexedDB，旧演示占位记录不冒充真实图片。

## 2026-09-28 · 可读性与列表规则

- 正文/已选值使用深色，辅助文字保持可读；主要信息、标题和金额通过字重与字号区分，避免整页等权。
- 金额统一两位小数、不加千分符、字重 700；旧历史金额也按相同规则展示。
- 筛选控件 32px，编辑表单保持 40px。列表最大 1440px；店铺资料及服务编辑器最大 1120px。
- 列表行内：待办浅蓝底，常规操作文字按钮，删除红色文字；实心主按钮用于页面创建与弹窗提交。
- 使用页码分页，跟随列表底部，翻页返回列表起点；服务/案例每页 8，园区每组 9，评价 10，其余表格和开票选择 20。替代此前服务每页 20 条的 UI 约定。
- 表单错误就地标红，提交跨步骤检查返回错误步骤；普通弹窗按内容定高并居中，正文超长时独立滚动。
- 商户档案头部操作在所有页签保留，以本轮用户批注覆盖旧的页签限制。
- 具体设计依据、取舍和验证记录见 `docs/ui-readability-and-list-design.md`。
