# UI 项目偏好卡

适用范围：本仓库供应商端完整前端演示。需求以仓库根目录三份 PRD（入驻、服务上下架、完整交易流程）为准；入驻首页与入驻流程是全站视觉基线。

| 项目 | 当前约定 | 依据 |
| --- | --- | --- |
| 交付深度 | 可运行前端 Demo，模拟接口与数据明确标注 | 用户说明只做前端演示 |
| 业务范围 | 完成已定义的园区、店铺、服务、订单、售后、发票、钱包、评价、设置与入驻闭环；未定义的其他类型不填业务字段 | 用户指示与三份 PRD |
| 主题 | 浅色、干净、清晰，参考 Linear 的视觉秩序 | 用户反馈 |
| 设备范围 | 桌面工作台优先；侧栏常驻，窄窗口不出现关键操作遮挡 | 当前项目结构与用户反馈 |
| 语言 | 简体中文 | 项目现有界面与 PRD；其他语言待业务决定 |
| 动效 | 仅快速的悬停、聚焦与状态反馈 | 用户要求填表干脆利索、做好交互反馈 |
| 无障碍专项 | 不启用 | 用户明确答复“默认不启用” |
| 设计版本 | V2 清亮版默认，V1 保留对比 | 用户要求作为验收工具中的新版本 |
| 数据与接口 | 本地模拟，不上传真实主体资料 | 前端 Demo 范围 |

2026-09-24：继承已确认的入驻 V2 视觉，推广到所有导航页。交易与服务的园区运营、客户端、支付平台及财务回调由验收工具模拟；未提供真实 API 的内容只做前端演示。附加能力选择延续既有约定，不重复询问。

## 经批注确认的设计判断（2026-09-24）

- 先按用户的决策顺序组织页面：对象名称和当前状态优先，分类、时间及补充描述降为次级；主操作靠近页面标题或当前对象，不悬在无关联的位置。
- 简洁是信息取舍与稳定对齐，不是把字段平铺。首屏先看任务和状态，编辑表单按真实工作步骤分组，列表保持可扫描的密度，并为数量增长准备明确的分页或筛选方式。
- 一级、二级页面不展示不可交互的面包屑；确需三级导航时，补可点击的返回路径。页面标题图标与侧栏的同一业务图标一致；区块标题图标传达各自语义，子字段不用重复图标。
- 图片上传入口与预览区域优先合一，保存前后均可辨认结果；图片支持查看大图。操作图标与文字留约 4px 间距，状态图标与文字垂直居中。
- 反馈消息和二次确认属于全站共享组件：标题显著、图文对齐、长文案可读、操作结果明确。按钮与标签延续入驻 V2 的圆角矩形，颜色只强调当前状态和主要动作。
- 我的园区的“查看园区客户端”在 PRD 中规定同号 SSO 跳转；是否当前页打开还是新页打开尚未定。当前演示沿用站内跳转，待园区客户端接入方案确定后决定打开方式与返回路径。
- 钱包内部由支付平台提供，供应商端只设计承载、开户状态和未接入状态，不用本地订单估算资产、明细或提现规则。
