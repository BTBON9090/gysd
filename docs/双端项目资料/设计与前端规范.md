# 双端设计与前端规范

更新：2026-10-28。用于新功能、新页面和已有页面迭代。依据现有项目偏好卡、政企园区设计资料及代码入口；各端具体页面的最新已确认决定优先。

## 共同设计原则

- 信息顺序跟随任务：对象和当前状态先于补充说明；主要操作靠近相关内容。列表便于扫描，表单按真实步骤分组，详情明确下一步。
- 专业、清晰、可信；使用浅色基底、蓝色主操作和有文字的语义状态。保留层次与适当密度，不靠大面积空白或重复卡片营造层次。
- 一个区域突出一个主要动作；普通、危险、不可操作状态可辨认。表单标签常驻、错误就近显示，提交中、空、错误及成功状态要有明确反馈。
- 遵循现有按钮、输入、对话框、列表、图片和图标系统。相同语义一致表达；不同业务状态不因外观相似被合并。
- 图片真实、用途明确，缺图有合适占位；不要制造认证、统计、服务承诺或其他未经证实的信息。业务页面避免混入开发说明。
- 交互动效服务反馈，避免影响办理效率。各端沿用已有无障碍选择与组件原有能力；供应商端偏好卡记载专项不启用。

## 供应商端：经营工作台

- 桌面管理后台，浅色、清晰、高信息密度、弱阴影。主色以 `src/styles/tokens.css` 的 `--brand` 为准（当前 `#3b63d3`）；成功绿、危险红、提醒黄按语义使用。
- 固定侧栏和工作区，列表最大内容宽度按 `--biz-content-width`（当前 1440px）；表单与详情按偏好卡约定 800–1200px 居中。小于 1200px 的桌面内容在主区域横向滚动。
- 筛选控件约 32px，编辑控件约 40px；分页靠列表底部。标题、状态、金额、操作层次清楚；金额按偏好卡两位小数、不加千分符。
- 常规列表操作为文字按钮，危险删除用红色；页面创建及弹窗提交使用主按钮。状态带文字，确认通过使用成功色。弹窗正文超长独立滚动。
- 订单详情沿用进度、页签、阶段与概要模式；签约历史用紧凑纵向时间线。服务案例选择在宽空间双列、较窄时单列，封面、文字和选中状态清楚。
- 店铺 Logo 上传用方形框，缺图展示默认店铺图标；素材上传、预览与替换沿用已有组件。视觉与具体尺寸以最新实现和偏好卡为准。
- Vue 3 + Element Plus + Pinia；优先 `AppShell`、`BizStateView`、`ListPagination`、`MoneyText`、`MediaUploadTile` 等现有组件。样式先找 token 和公共样式，避免新建全局覆盖。

## 政企园区：面向企业的门户

- 兼顾平台展示和服务选择：可使用真实运营图片、较丰富的首页视觉，服务列表、详情和个人中心保持紧凑与清晰。首页 V2/V3/V4 有不同方向，先检查实际启用版本和对应约定，不把某一版视觉强制套到所有页面。
- 当前设计文档中的默认品牌蓝为 `#2460d2`；主按钮纯色、导航选中下划线。品牌及主题以 `src/styles/tokens.css` 和 `controls.css` 的实际实现为准。
- 复用 `Shell`、`Breadcrumb`、`Input`、`Modal`、`EmptyState`、`ServiceCard`、`ContentImage`；宣传素材使用真实图片位，缺图按照对应组件和已确认的场景规则处理。
- 兼顾桌面与移动端：按页面既有断点调整列数、侧栏与导航；检查窄屏表单、长文本及横向溢出。不要把供应商端的桌面专用宽度强加给门户。
- React + TypeScript；业务组件通过 gateway 获取数据，沿用 Zod、TanStack Query 与现有模型。生产构建不混入演示数据或验收捷径，接口错误不能表现为成功。

## 新页面交付检查

1. 确认所属端、用户角色、业务来源、版本及关联页面；检查相关已有组件和 token。
2. 明确主路径与权限、状态、空/加载/失败、长内容和图片缺省；跨端数据列出来源和未确定项。
3. 先做代表页面并在目标视口检查，随后扩展相同模式；实现时避免重复维护状态和视觉变量。
4. 执行所在项目的类型检查和构建，按风险检查关键交互及响应式；说明演示、真实接口与未验证边界。
5. 业务决定或视觉变化经确认后回写原有偏好卡/设计文档并更新本索引；不将未经验证的建议写成已确认规则。
